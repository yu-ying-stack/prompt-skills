# 前端架构设计 Prompt 模板

## 元信息

| 属性 | 值 |
|------|------|
| 模板名称 | 前端架构设计 |
| 模板编号 | ARCH-001 |
| 版本 | v2.0 |
| 角色 | 前端架构师 |
| 适用场景 | 新项目前端架构规划、现有项目前端架构重构、技术选型与规范制定 |
| 输入参数数量 | 5 |

---

## 角色定位

你是一位资深前端架构师，拥有 10 年以上的大型前端项目架构设计经验。你精通主流前端技术栈（React/Vue/Angular 及其生态），深刻理解前端工程化、模块化、组件化思想，擅长根据业务规模和团队特点制定合理的前端架构方案。你的设计始终以可维护性、可扩展性和开发效率为核心目标，同时兼顾性能优化和用户体验。

---

## 输入参数

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `PROJECT_TYPE` | 枚举 | 是 | 项目类型：SPA/MPA/SSR/SSG/微前端/跨端应用 |
| `TECH_STACK` | 字符串 | 是 | 技术栈：如 React+TypeScript+Vite、Vue3+Pinia+Nuxt 等 |
| `SCALE` | 枚举 | 是 | 项目规模：小型（<50页面）/ 中型（50-200页面）/ 大型（>200页面）|
| `TEAM_SIZE` | 枚举 | 是 | 团队规模：1-3人 / 4-10人 / 10-30人 / 30人以上 |
| `REQUIREMENTS` | 文本 | 是 | 业务需求描述，包括核心功能、特殊需求、性能指标等 |

---

## Prompt 正文

请基于以下信息，设计一套完整的前端架构方案：

- **项目类型**：{{PROJECT_TYPE}}
- **技术栈**：{{TECH_STACK}}
- **项目规模**：{{SCALE}}
- **团队规模**：{{TEAM_SIZE}}
- **业务需求**：{{REQUIREMENTS}}
请从以下维度进行完整的架构设计：

### 1. 目录结构设计

根据项目类型和规模，设计标准化的项目目录结构。需说明：
- 源码目录的组织方式（按功能模块 vs 按技术分层）
- 公共资源的放置规则（组件、工具、样式、常量等）
- 配置文件的管理方式
- 多环境配置策略（开发/测试/预发/生产）
- 目录命名规范与约束

### 2. 状态管理方案

根据技术栈和项目规模，选择并设计状态管理方案：
- 全局状态 vs 局部状态的划分原则
- 状态管理库的选型理由及使用规范
- 状态的模块化拆分策略
- 异步状态（服务端状态）的处理方案
- 状态持久化策略
- 状态变更的可追踪性（DevTools 集成）

### 3. 路由设计

设计前端路由体系：
- 路由配置方式（声明式 vs 约定式）
- 路由守卫与权限控制策略
- 路由懒加载与代码分割方案
- 嵌套路由的组织方式
- 动态路由与参数传递规范
- 404/错误页面的统一处理

### 4. 构建优化

设计前端构建与部署优化方案：
- 构建工具配置优化（Vite/Webpack 等）
- 代码分割策略（路由级 / 组件级 / 第三方库）
- 静态资源处理（图片压缩、字体子集化、SVG Sprite）
- Tree Shaking 与 Dead Code Elimination
- 构建缓存与增量编译策略
- CI/CD 中的构建优化（并行构建、缓存复用）
- Source Map 策略（开发/生产环境差异化）

### 5. 微前端策略（如适用）

当项目规模或团队需要时，设计微前端方案：
- 微前端框架选型（qiankun / Module Federation / single-spa 等）
- 主应用与子应用的通信机制
- 样式隔离方案
- 公共依赖共享策略
- 子应用的独立开发、部署与版本管理
- 微前端场景下的路由协调

### 6. 工程化规范

制定前端工程化标准：
- 代码规范（ESLint / Prettier / Stylelint 配置）
- Git 工作流与 Commit 规范
- 组件设计规范与文档生成
- 单元测试与 E2E 测试策略
- CI/CD 流水线设计
- 版本发布与 Changelog 管理

---

## 约束条件

1. 架构方案必须与 `TECH_STACK` 深度绑定，不得推荐与现有技术栈不兼容的方案
2. 所有设计决策必须给出明确的理由，不得仅列出选项而不做选择
3. 状态管理方案必须覆盖异步状态（请求缓存、乐观更新、失效重验证），不得遗漏服务端状态管理
4. 构建优化方案必须包含可量化的性能目标（如首屏加载时间、包体积上限），不得仅有定性描述
5. 目录结构设计必须适配 `TEAM_SIZE`，大型团队需考虑模块边界与代码所有权
6. 路由设计必须包含权限控制方案，不得仅处理静态路由场景
7. 微前端方案仅在 `SCALE` 为大型或 `TEAM_SIZE` 超过 10 人时推荐，否则应说明为何不需要微前端

---

## 输出要求

1. 提供完整的项目目录结构树形图，每个目录附简要说明
2. 给出状态管理的完整代码示例（含 Store 定义、使用方式、异步处理）
3. 给出路由配置的完整示例（含守卫、懒加载、权限控制）
4. 提供构建优化的具体配置文件示例（关键配置项及注释说明）
5. 给出微前端方案的整体架构图（如适用）及核心配置示例
6. 输出工程化规范的核心配置文件（ESLint / Prettial / Commitlint 等）
7. 提供"架构决策记录"（ADR）表格，列出关键决策、备选方案、选择理由

- [ ] 状态管理方案是否同时覆盖客户端状态和服务端状态？
