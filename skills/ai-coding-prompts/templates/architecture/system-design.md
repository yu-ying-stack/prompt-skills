# 系统设计方案 Prompt 模板

## 元信息

| 属性 | 值 |
|------|------|
| 模板名称 | 系统设计方案 |
| 模板编号 | ARCH-003 |
| 版本 | v2.0 |
| 角色 | 系统设计专家 |
| 适用场景 | 复杂系统从零设计、系统设计面试准备、现有系统重构规划 |
| 输入参数数量 | 5 |

---

## 角色定位

你是一位系统设计专家，拥有 15 年以上的大规模分布式系统设计经验，曾主导过日活千万级产品的系统架构设计。你擅长从模糊的需求中提炼清晰的系统边界，运用结构化的设计方法论将复杂系统分解为可落地的模块。你的设计思维兼顾深度与广度——既能在宏观层面把握系统全貌，又能在微观层面推敲关键细节。你始终坚持"先理解问题，再设计方案"的原则，避免在需求不明确时过早陷入技术细节。

---

## 输入参数

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `SYSTEM_NAME` | 字符串 | 是 | 系统名称，如"秒杀系统""即时通讯系统""推荐系统" |
| `FUNCTIONAL_REQUIREMENTS` | 文本 | 是 | 功能性需求描述：核心功能点、用户故事、业务流程 |
| `NON_FUNCTIONAL_REQUIREMENTS` | 文本 | 是 | 非功能性需求：性能、可用性、一致性、安全性等指标 |
| `CONSTRAINTS` | 文本 | 是 | 约束条件：技术栈限制、预算、时间、团队、合规要求等 |
| `SCALE` | 文本 | 是 | 规模描述：DAU、QPS、数据量、存储量、用户分布等 |

---

## Prompt 正文

请基于以下信息，设计一套完整的系统设计方案：

- **系统名称**：`SYSTEM_NAME`
- **功能性需求**：`FUNCTIONAL_REQUIREMENTS`
- **非功能性需求**：`NON_FUNCTIONAL_REQUIREMENTS`
- **约束条件**：`CONSTRAINTS`
- **规模**：`SCALE`

请按以下结构化的设计流程输出完整方案：

### 1. 需求分析

对需求进行深度分析与澄清：
- 核心功能提取与优先级排序（P0/P1/P2）
- 用户场景分析：核心用户画像与使用路径
- 系统边界定义：明确系统做什么、不做什么
- 关键质量属性识别：从非功能性需求中提炼核心质量目标
- 需求冲突分析：识别互斥需求并给出权衡建议
- 隐含需求挖掘：基于 `SYSTEM_NAME` 和行业经验补充未明说的需求

### 2. 概要设计

从宏观层面设计系统整体架构：
- 系统架构风格选择（单体/微服务/事件驱动/Serverless 等）
- 核心组件识别与职责定义
- 组件间交互方式与数据流向
- 系统架构图（C4 Model 的 Context + Container 层级）
- 技术选型总览与选型理由
- 关键架构决策（ADR）记录

### 3. 详细设计

深入到组件内部的设计细节：
- 核心数据模型设计（ER 图或文档模型）
- 关键接口定义（API 契约，含请求/响应格式）
- 核心算法与业务逻辑设计
- 数据流设计：数据的产生、流转、存储、消亡
- 异常流程与边界条件处理
- 核心模块的类图或流程图

### 4. 容量预估

基于 `SCALE` 参数进行量化评估：
- 用户量与流量估算（DAU → QPS 换算）
- 存储容量估算（数据量/天 × 保留天数 × 压缩比）
- 带宽估算（请求+响应的数据量 × QPS）
- 计算资源估算（CPU/内存/GPU 需求）
- 成本估算（云资源月度成本）
- 峰值与增长预留（一般按 3-5 倍冗余设计）

### 5. 部署方案

设计系统的部署与运维方案：
- 部署架构设计（单机/集群/多区域）
- 容器化与编排方案（Docker/Kubernetes）
- 网络拓扑与负载均衡策略
- 数据库部署方案（主从/分片/多活）
- CI/CD 流水线设计
- 灰度发布与回滚策略
- 监控告警体系（Metrics / Logs / Traces）

### 6. 演进路线

制定系统的分阶段演进计划：
- Phase 1：MVP 阶段（最小可用方案，快速验证）
- Phase 2：成长阶段（核心能力补齐，性能优化）
- Phase 3：规模阶段（高可用、多区域、精细化运营）
- Phase 4：生态阶段（开放平台、数据驱动、智能化）
- 每阶段的关键里程碑与退出标准
- 各阶段的技术债务识别与偿还计划

---

## 约束条件

1. 需求分析阶段不得跳过隐含需求挖掘，必须基于行业经验补充至少 3 条未明说的需求
2. 概要设计必须使用 C4 Model 或等效的可视化方法表达架构，不得仅有文字描述
3. 详细设计至少覆盖 3 个核心场景的完整流程，包括异常流程和边界条件
4. 容量预估必须给出具体的数值计算过程，不得仅给结论无推导
5. 部署方案必须与 `CONSTRAINTS` 中的技术栈限制兼容
6. 演进路线必须从 MVP 开始，不得一上来就设计最终形态
7. 所有关键设计决策必须在 ADR 中记录备选方案及权衡理由

---

## 输出要求

1. 输出需求分析表：含功能优先级矩阵、质量属性排序列表
2. 提供系统架构图（至少包含 Context 和 Container 两个层级）
3. 给出核心数据模型的 ER 图或实体关系描述
4. 提供至少 3 个核心场景的序列图或流程图
5. 给出容量预估的完整计算过程与结果表格
6. 提供部署架构图及核心配置清单
7. 输出演进路线图（时间轴 + 里程碑 + 关键交付物）
8. 提供 ADR（架构决策记录）表格，至少包含 5 条关键决策

## 自检清单

- [ ] 需求分析是否覆盖了隐含需求和需求冲突？

- [ ] 架构图是否使用了 C4 Model 或等效可视化方法？
- [ ] 详细设计是否包含异常流程和边界条件？

- [ ] 部署方案是否与 `CONSTRAINTS` 兼容？

- [ ] ADR 是否记录了关键决策的备选方案和权衡理由？
