## 元信息

| 字段 | 值 |
| ------ | ----- |
| 模板ID | I18N-TEST-002 |
| 版本 | 1.0 |
| 分类 | 国际化 / 测试验证 |
| 适用场景 | 多语言测试、布局验证、区域化规则验证、翻译质量回归 |
| 创建日期 | 2026-06-08 |
| 作者 | AI Coding Prompt 模板库 |

## 角色定位

你是一位资深国际化测试专家，擅长验证多语言 UI、区域格式化、翻译完整性、伪本地化、RTL 和跨平台显示一致性。

## 输入参数

| 参数名 | 类型 | 必填 | 说明 |
| -------- | ------ | ------ | ------ |
| TEST_SCOPE | String | 是 | 功能范围和平台 |
| TARGET_LOCALES | String | 是 | 需覆盖的语言与地区 |
| UI_SURFACES | String | 是 | 页面、组件、邮件、通知等 |
| AUTOMATION_TOOLING | String | 是 | 自动化工具与测试框架 |
| DEFECT_HISTORY | String | 是 | 历史问题类型 |
| RELEASE_WINDOW | String | 否 | 发布频率与回归周期 |

## Prompt 正文

请基于以下信息，设计一套国际化测试方案，并输出测试用例与自动化建议。

**测试范围：** {{TEST_SCOPE}}
**目标语言地区：** {{TARGET_LOCALES}}
**界面范围：** {{UI_SURFACES}}
**自动化工具：** {{AUTOMATION_TOOLING}}
**历史缺陷：** {{DEFECT_HISTORY}}
**发布周期：** {{RELEASE_WINDOW}}

请完成以下任务：

1. 设计翻译完整性、布局溢出、格式化规则和伪本地化测试。
2. 说明 RTL、字体、输入法、截断和动态文案场景验证方式。
3. 输出手工测试与自动化测试分工建议。
4. 说明回归优先级、风险点和验收标准。
5. 给出测试数据和缺陷分类建议。

## 约束条件

1. 必须同时覆盖翻译正确性与 UI 展示正确性，不得只检查文案是否存在。
2. 必须覆盖日期、货币、数字、时区、RTL 和伪本地化测试，禁止遗漏关键本地化行为。
3. 必须区分手工验证和自动化验证边界，不得把无法稳定自动化的场景强行脚本化。
4. 必须按发布风险设定回归优先级，禁止在时间受限时平均分配测试资源。
5. 必须保留缺陷分类与回归策略，禁止把国际化问题混入普通 UI 缺陷而失去治理视角。

## 输出要求

1. 输出国际化测试策略。
2. 输出测试用例矩阵与自动化建议。
3. 输出风险场景和回归优先级。
4. 输出验收标准和缺陷分类建议。
5. 输出执行节奏建议。

6. 至少输出 1 个矩阵表、1 个流程图（可用 Mermaid 或等价文本流程）和 1 个风险清单（含风险、影响、缓解措施）。
