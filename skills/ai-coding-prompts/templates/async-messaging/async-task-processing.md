## 角色定位

你是一位资深后端与平台架构师，擅长设计异步任务系统、任务编排、调度、重试、补偿和执行隔离策略。

## 输入参数

| 参数名 | 类型 | 必填 | 说明 |
| -------- | ------ | ------ | ------ |
| TASK_SCENARIO | String | 是 | 任务业务场景 |
| EXECUTION_MODEL | String | 是 | 执行模型，如 队列消费、Cron、工作流引擎 |
| SLA_REQUIREMENTS | String | 是 | 成功率、时效、重试窗口 |
| IDEMPOTENCY_REQUIREMENTS | String | 是 | 幂等、去重和补偿要求 |
| RESOURCE_LIMITS | String | 是 | 并发、资源限制和隔离要求 |
| FAILURE_HANDLING | String | 否 | 超时、中断、人工介入场景 |

## Prompt 正文

请基于以下信息，设计一套异步任务处理方案，并输出任务生命周期与执行治理规则。

**任务场景：** {{TASK_SCENARIO}}
**执行模型：** {{EXECUTION_MODEL}}
**SLA 要求：** {{SLA_REQUIREMENTS}}
**幂等要求：** {{IDEMPOTENCY_REQUIREMENTS}}
**资源限制：** {{RESOURCE_LIMITS}}
**失败处理：** {{FAILURE_HANDLING}}

请完成以下任务：

1. 设计任务状态机、任务表或任务元数据结构。
2. 说明任务分发、并发控制、抢占策略、超时与取消逻辑。
3. 给出重试、补偿、死信、人工介入和审计方案。
4. 说明监控指标、调度看板和运维排障方法。
5. 给出实施步骤和示例伪代码。

## 约束条件

1. 必须定义清晰的任务状态机，不得使用无法审计的隐式状态流转。
2. 必须说明幂等、去重、重试和补偿策略，禁止把失败任务简单丢弃。
3. 必须定义超时、取消、并发上限和资源隔离规则，不得让单类任务挤占全部执行资源。
4. 必须说明人工介入与审计追踪机制，禁止输出黑盒化的后台任务系统。
5. 必须说明任务数据一致性与恢复策略，不得依赖人工修改数据库修复主流程。

## 输出要求

1. 输出任务生命周期与状态机。
2. 输出调度、执行、失败治理方案。
3. 输出数据结构或任务表设计。
4. 输出监控指标与运维建议。
5. 输出示例代码或伪代码。

6. 至少输出 1 个矩阵表、1 个流程图（可用 Mermaid 或等价文本流程）和 1 个风险清单（含风险、影响、缓解措施）。
