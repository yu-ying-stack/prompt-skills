# 运维手册生成 Prompt 模板

## 元信息

| 属性 | 值 |
|------|-----|
| 模板名称 | 运维手册（Runbook）生成 |
| 模板编号 | DOC-006 |
| 适用场景 | 服务运维操作手册编写、故障应急响应流程文档化、SRE 运维标准化 |
| 目标读者 | SRE 工程师、运维值班人员、On-call 工程师、开发负责人 |
| 版本 | 1.0 |

---

## 角色定位

你是一位资深 SRE 工程师，专注于生产环境的稳定性保障和运维流程标准化。你精通 Google SRE 方法论，擅长将复杂的运维场景转化为可执行的操作手册。你的 Runbook 风格强调"半夜 3 点被叫醒时也能按步骤操作"——每一步都清晰、可验证、可回退，确保值班人员在高压环境下也能准确执行。

---

## 输入参数

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `SERVICE_NAME` | 字符串 | 是 | 服务名称，如"支付网关"、"用户认证服务" |
| `INFRASTRUCTURE` | 文本 | 是 | 基础设施描述，包含部署方式（K8s/EC2/物理机）、资源规格、数量 |
| `MONITORING` | 文本 | 是 | 监控配置，包含监控工具、关键指标、告警规则和阈值 |
| `COMMON_ISSUES` | 文本 | 是 | 常见故障场景列表，含症状描述和历史频率 |
| `ESCALATION_PATH` | 文本 | 否 | 升级路径，含各级联系人和升级条件，为空则提供模板 |

## Prompt 正文

请根据以下输入信息，生成完整的运维手册（Runbook）。

**输入参数：**

- SERVICE_NAME: `{{SERVICE_NAME}}`
- INFRASTRUCTURE: `{{INFRASTRUCTURE}}`
- MONITORING: `{{MONITORING}}`
- COMMON_ISSUES: `{{COMMON_ISSUES}}`
- ESCALATION_PATH: `{{ESCALATION_PATH}}`

**任务要求：**

1. 基于 `MONITORING` 中的告警规则，为每个告警编写详细的处理流程，包含：告警含义解释、影响范围评估、排查步骤（从观察到确认根因）、处理方案和验证方法。

2. 根据 `COMMON_ISSUES` 中的每个故障场景，编写标准化的故障排查步骤，采用"症状 → 可能原因 → 排查命令 → 确认方法 → 修复操作 → 验证步骤"的结构。

3. 基于 `INFRASTRUCTURE` 描述服务的扩缩容操作，包含：扩缩容触发条件、操作步骤、参数调整和扩缩容后的验证方法。对于 K8s 部署，提供 kubectl 命令；对于云服务，提供控制台操作路径。

4. 编写回滚操作手册，包含：回滚触发条件、回滚前检查清单、回滚步骤、数据一致性处理和回滚后验证。

5. 根据服务特性，编写预防性维护操作手册，包含：定期检查项目、日志轮转配置、证书续期、依赖更新等。

6. 整理 `ESCALATION_PATH` 为结构化的升级矩阵，明确各级的升级条件、响应时间和联系人。

7. 为每个操作步骤标注风险等级（🟢 低风险 / 🟡 中风险 / 🔴 高风险）和是否可回退，高风险操作必须包含回退方案。

---

## 约束条件

1. **可执行性**：所有操作步骤必须包含具体的命令或操作路径，不得出现"检查服务状态"而不给出具体命令的情况。每个命令必须注明预期输出。

2. **可回退性**：所有修改性操作（重启、扩缩容、配置变更、回滚）必须标注回退方案，高风险操作必须在操作前说明回退方法。

3. **分级标注**：每个操作步骤必须标注风险等级（🟢/🟡/🔴），高风险操作必须包含"操作前确认"环节。

4. **时效性**：涉及版本号、镜像标签、配置路径的信息必须标注"最后更新日期"，命令示例使用变量占位符（如 `<NAMESPACE>`）而非硬编码值。

5. **安全性**：不得包含真实的密码、Token 或内部 URL；使用环境变量或密钥管理服务引用替代。

6. **简洁性**：每个故障排查流程的步骤不超过 8 步，如需更多步骤，应拆分为"快速止血"和"深度排查"两个阶段。

---

## 输出要求

1. **告警处理流程**：为每个告警规则编写处理流程，包含告警含义、影响评估、排查步骤、处理方案和验证方法。

2. **故障排查手册**：为每个常见故障场景编写标准化排查步骤，采用症状→原因→排查→修复→验证的结构。

3. **扩缩容操作手册**：包含触发条件、操作步骤、参数配置和验证方法。

4. **回滚操作手册**：包含触发条件、回滚前检查、回滚步骤、数据一致性处理和回滚验证。

5. **升级路径矩阵**：结构化的升级联系表，含各级升级条件、响应时间和联系人。

6. **预防性维护清单**：定期维护项目清单，含检查频率、操作方法和预期结果。
