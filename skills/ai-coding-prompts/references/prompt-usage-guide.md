# Prompt 使用规范与安全指南

## 一、使用流程

### 1.1 标准工作流

```
选择模板 → 填充变量 → AI 生成 → 人工 Review → 单元测试 → 集成测试 → Code Review → 合并
```

### 1.2 流程说明

| 步骤 | 负责人 | 输出物 | 通过标准 |
|------|--------|--------|---------|
| 选择模板 | 开发者 | 完整 Prompt | 变量完整填充 |
| AI 生成 | AI | 代码/方案 | - |
| 人工 Review | 开发者 | 修改后代码 | 理解全部逻辑 |
| 单元测试 | 开发者 | 测试通过 | 覆盖率 ≥ 80% |
| 集成测试 | 开发者 | 测试通过 | 主流程覆盖 |
| Code Review | 审查者 | 审查意见 | 无阻塞性问题 |
| 合并 | 审查者 | 合入主干 | CI 全绿 |

### 1.3 关键原则
- AI 生成的代码**必须经过人工审查**后才能合入
- 开发者必须**完全理解**生成代码的逻辑
- 不理解的代码等同于不合格代码

## 二、版本管理

### 2.1 存储位置
```
项目根目录/docs/ai-prompts/
```

### 2.2 命名规范
```
{场景}_{技术栈}_v{版本}.md
```
示例：
- `codegen_react_v1.md`
- `review_python_v2.md`
- `test_java_v1.md`

### 2.3 版本控制
- 每次模板修改需提交 PR
- PR 描述中说明修改原因和影响范围
- 重大变更需要 Tech Lead 审批

## 三、安全红线（禁止项）

### 3.1 绝对禁止

| 编号 | 禁止行为 | 风险等级 | 说明 |
|------|---------|---------|------|
| S-01 | 在 Prompt 中粘贴生产环境密钥/Token/密码 | 致命 | 可能导致密钥泄露 |
| S-02 | 要求 AI 生成绕过安全机制的代码 | 致命 | 违反安全合规 |
| S-03 | 将 AI 生成代码不经审查直接部署到生产环境 | 高危 | 可能引入未知漏洞 |
| S-04 | 在 Prompt 中暴露用户隐私数据（PII） | 高危 | 违反数据保护法规 |
| S-05 | 使用 AI 生成加密/签名等安全关键算法 | 高危 | 可能存在实现缺陷 |

### 3.2 需特别注意

- 涉及金融计算的代码需额外的精度验证
- 涉及并发控制的代码需竞态条件测试
- 涉及数据迁移的脚本需在测试环境充分验证
- 生成的 SQL 需在只读副本验证后再执行

## 四、效果评估

### 4.1 评估频率
- 月度由 Tech Lead 抽检
- 季度团队回顾

### 4.2 评估维度

| 维度 | 指标 | 目标 |
|------|------|------|
| 功能正确性 | 生成代码一次通过率 | ≥ 70% |
| 安全漏洞 | 安全问题发现率 | 0 致命/高危 |
| 代码重复 | 重复代码比例 | ≤ 10% |
| 维护成本 | 后续修改频率 | 低于手写代码 |
| 开发效率 | 任务完成时间 | 提升 ≥ 30% |

### 4.3 持续优化
- 收集使用反馈，月度更新模板
- 记录失败案例，完善约束条件
- 跟踪行业最佳实践，引入新模板
